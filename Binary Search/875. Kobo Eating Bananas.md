## Problem
You are given an integer array `piles` where `piles[i]` is the number of bananas in the `ith` pile. You are also given an integer `h`, which represents the number of hours you have to eat all the bananas.

You may decide your bananas-per-hour eating rate of `k`. Each hour, you may choose a pile of bananas and eats `k` bananas from that pile. If the pile has less than `k` bananas, you may finish eating the pile but you can not eat from another pile in the same hour.

Return the minimum integer `k` such that you can eat all the bananas within `h` hours.

## Example
```python
Input: piles = [1,4,3,2], h = 9

Output: 2
```

## Solution
```python
from math import ceil

class Solution:
    def minEatingSpeed(self, piles: List[int], h: int) -> int:
        def binary(h: int, front: int, end: int, k: int) -> int:
            if front <= end:
                mid = (front + end) // 2
                hours_taken = 0
                for x in piles:
                    hours_taken += ceil(x / mid)
                if hours_taken <= h:
                    return binary(h, front, mid - 1, mid)
                else:
                    return binary(h, mid + 1, end, k)
            else:
                return k

        return binary(h, 1, max(piles), max(piles))
```

Since we know that the maximum bananas-per-hour eating rate (k) must be the greatest number in the piles array, we can set that as our default bananas-per-hour eating rate.

Using the front value of 1 and the end value of the maximum number in the pile, we can utilize a binary search to find the minimum integer k that will allow Kobo to eat all the bananas within (h) hours.

In the binary search, we can get the middle number within the range (1 to max(piles) first) and then use that to compute the total number of hours taken to eat all piles `sum(ceil(# of bananas / mid) for pile in piles)`.

Using that info, we can check if the hours taken is less than or equal to the passed in hour limit (h).

If it is less or equal, then we know that there could be a slower eating rate in the lower half within the range (1 to (max(piles) // 2)).

However if it is greater, then we know that there could be a faster eating rate in the upper half within the range ((max(piles) // 2) to max(piles)).

> Remember, dividing the same number by a **smaller** number will increase the result while dividing the same number by a **larger** number will decrease the result.
> So, when we get the sum of the ceils (the hours taken at that eating rate), if that sum is **less** than the time limit (h) that means the current eating rate is either perfect or too fast, so we keep searching the **lower** halves of the range.
> Likewise, when we get the sum of the ceils (the hours taken at that eating rate), if that sum is **greater** than the time limit (h) that means the current eating rate is too slow, so we keep searching the **upper** halves of the range.
